# PyCon Ireland website

Source code for the PyCon Ireland conference website. This repository is the shared base for **every edition** of the conference: the 2026 edition (21 November 2026, Dublin) has just taken place, and the 2027 edition will be built and published from the same code.

## Editions

Each edition lives on its own branch and is deployed to its own Netlify site and subdomain.

| Edition | Branch | URL | Status |
|---------|--------|-----|--------|
| 2026 | `2026` | https://2026.pycon.ie/ | Archived (event over) |
| 2027 | `main`, then `2027` | https://2027.pycon.ie/ | In preparation |

### How the branches work

- **`main`** holds the shared code (templates, partials, styles, scripts, CI) and the edition currently being prepared.
- **One branch per edition** (`2026`, `2027`, ...) freezes the site of that year. It keeps receiving small edition-specific updates (post-event thank-you, photos, videos) after the conference.
- Generic fixes and improvements go to `main` first, then are cherry-picked into an edition branch when that site needs them.

### What is specific to an edition

| File | Edition-specific content |
|------|--------------------------|
| `hugo.toml` | `baseURL`, event dates (`eventStartDate` / `eventEndDate`), venue, `sessionizeApiUrl`, `ticketsUrl`, hero text |
| `mise.toml` | `NETLIFY_SITE_ID` of the edition's Netlify site |
| `data/*.yml` | Sponsors, organising team, "Discover Dublin" content |
| `content/` | Blog posts, CFP, venue, about pages |
| `assets/img/`, `static/img/` | Hero image, OG image, venue photos |
| `content/credits.md` | Photo and image attribution |

### Starting a new edition

1. Create the edition branch from `main` (for example `git switch -c 2027 main`) once the site is ready to go live, or keep working on `main` until then.
2. Create a new Netlify site for the edition and set its id in `mise.toml` (`NETLIFY_SITE_ID`).
3. Point the `<year>.pycon.ie` subdomain to that Netlify site.
4. In `hugo.toml`, update `baseURL`, the event dates (Dublin is on GMT `+00:00` in November, IST `+01:00` in summer), the venue, and the Sessionize and Tito URLs of the new event.
5. Reset edition content: sponsors in `data/sponsors.yml`, blog posts in `content/blog/`, CFP dates, venue page.
6. Replace images and update `content/credits.md` accordingly.

## Tech Stack

- **[Hugo](https://gohugo.io/) v0.170.1** (extended): static site generator
- **[Tailwind CSS](https://tailwindcss.com/) v4**: via Hugo's native `css.TailwindCSS` pipe (no PostCSS or external build tools needed)
- **Inter** (Google Fonts) for body text, **Bree** (Adobe Fonts) for brand headings
- **[Sessionize](https://sessionize.com/)**: speakers, sessions and schedule (embedded widgets plus JSON fetched at build time)
- **[Tito](https://ti.to/)**: ticket sales (widget plus prices fetched at build time)
- **Vanilla JS**: mobile menu and anchor scrolling only, no frameworks

Hugo processes Tailwind CSS natively through its asset pipeline. The `hugo_stats.json` file (generated by Hugo's `buildStats`) tracks CSS class usage across templates, enabling Tailwind to tree-shake unused styles. CSS rendering is deferred via `templates.Defer` to ensure all classes are captured before processing.

## Prerequisites

- [Hugo Extended](https://gohugo.io/installation/) >= 0.170.1
- [Node.js](https://nodejs.org/) >= 20
- [Python](https://www.python.org/) 3.13 (only for the helper scripts in `scripts/`)

If you use [mise](https://mise.jdx.dev/), Hugo and Python are pinned in `mise.toml`.

## Getting Started

```bash
npm install          # install Tailwind CSS
hugo server          # start dev server with live reload
```

Open http://localhost:1313/ in your browser.

## Build for Production

```bash
hugo --minify
```

Output goes to `public/`. CSS is minified and fingerprinted automatically in production builds.

## Adding Content

**Speakers, sessions and schedule**: managed in Sessionize. The embedded widgets update on their own; trigger a new deploy so the JSON-LD structured data (built from `sessionizeApiUrl`) picks up the changes.

**Tickets**: managed in Tito. Ticket names, prices and sale state are fetched at build time; redeploy after a change.

**Sponsors**: edit `data/sponsors.yml`. Sponsors are grouped by tier (Platinum, Gold, Silver, Community).

**Blog posts**: add a Markdown file in `content/blog/`:

```markdown
---
title: "Post Title"
date: 2026-03-01
description: "Short description."
---

Post content here.
```

**Images**: always add the attribution to `content/credits.md`.

## Design

Dark theme with Python brand colours as accents:

| Token | Colour | Usage |
|-------|--------|-------|
| `py-blue` | `#306998` | Primary accent, buttons, links |
| `py-yellow` | `#FFD43B` | Secondary accent, highlights |
| `bg-primary` | `#0f1117` | Page background |
| `bg-card` | `#1a1d2e` | Card surfaces |

Theme tokens are defined in `assets/css/main.css` using Tailwind v4's `@theme` directive.

## Deployment

Each edition is deployed by [Netlify](https://www.netlify.com/) to its own site (see [Editions](#editions)). Settings live in `netlify.toml`:

- Build command: `npm install && hugo --minify`
- Publish directory: `public/`
- Hugo 0.170.1, Node 22, `TZ=Europe/Dublin`

The Netlify CLI picks the right site from `NETLIFY_SITE_ID` in `mise.toml`, so no `netlify link` is needed.

### Content Security Policy

Security headers, including the CSP, are defined in `static/_headers`. When adding a third-party script, stylesheet or font, add its domain to the CSP and run:

```bash
python scripts/check-csp.py --verbose
```

The same check runs in CI (`.github/workflows/csp-check.yml`) on pull requests touching `layouts/`, `static/_headers` or `csp-dynamic-loaders.yml`.
