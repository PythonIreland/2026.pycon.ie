## Project Overview

PyCon Ireland conference website: a Hugo static site with Tailwind CSS v4 native integration and comprehensive SEO structured data. The same code serves every edition.

### Editions and branches

| Edition | Branch | Netlify site | URL | Status |
|---|---|---|---|---|
| 2026 | `2026` | `pycon-ireland-2026` | https://2026.pycon.ie/ (also `pycon.ie`, `www.pycon.ie`) | Archived: post-event thank-you, links to 2027 |
| 2027 | `main` | `pycon-ireland-2027` | https://2027.pycon.ie/ | In preparation (`editionStatus = "planning"`) |

- `main` holds the shared code and the edition being prepared. PRs against `main` get previews from `pycon-ireland-2027`; PRs against `2026` from `pycon-ireland-2026`
- Generic fixes go to `main` first, then are cherry-picked into the `2026` branch when that site needs them (open a PR with base `2026`)
- Edition-specific content (dates, venue, sponsors, blog posts, Terms wording) must not leak from one branch to the other
- DNS for `pycon.ie` is on Cloudflare; edition subdomains are CNAMEs to their Netlify site, proxied, zone SSL mode "Full"

### Edition status (`params.editionStatus`)

- `"planning"` (current on `main`): `layouts/partials/planning-home.html` replaces the homepage ("in preparation", follow us, revisit 2026, sponsor/volunteer); no date, venue, tickets or Event JSON-LD; footer and `<title>` without date/venue; nav only shows menu entries with `[menus.main.params] planning = true` (`planningOnly = true` entries only show in planning); a `[[cascade]]` block at the end of `hugo.toml` stops building CFP, schedule, grid, speakers, sponsors, venue and Dublin (not built, not in the sitemap)
- `"announced"`: full conference site. To switch, set `editionStatus = "announced"`, remove the `[[cascade]]` block, and update the date, venue, CFP, Sessionize and Tito params (they still hold the 2026 values as a template)
- `params.edition` is the year shown in the hero, the planning homepage and the CFP badge; keep it in sync with `title` and `baseURL`
- The venue page and `venue-home.html` contain prose specific to the current venue: rewrite it when the venue changes

## Architecture

### Hugo + Tailwind v4 Native Integration

This project uses Hugo's **native Tailwind CSS processing** without PostCSS or Node.js build tools:

- `assets/css/main.css` — Tailwind v4 entry point with `@theme` directive for design tokens
- `hugo_stats.json` — Generated by Hugo's `buildStats`, tracks CSS class usage for tree-shaking
- `layouts/partials/css.html` — Uses `templates.Defer` to defer CSS rendering until all classes are collected

**How it works:**
1. Hugo scans all templates and generates `hugo_stats.json` with used classes
2. Tailwind CSS reads this via `@source "hugo_stats.json"` directive
3. Hugo's `css.TailwindCSS` pipe processes the CSS natively
4. CSS is minified and fingerprinted in production builds

### Data-Driven Content Model

Conference content is stored in **YAML data files** (`data/*.yml`), not Markdown frontmatter. Two kinds of content come from external services instead, fetched at build time with `resources.GetRemote`:

**Sessions and speakers: Sessionize**
- Source of truth: Sessionize. Pages embed the Sessionize widgets (`/schedule/`, `/grid/`, `/speakers/`)
- `params.sessionizeApiUrl` points to the JSON "All data" endpoint
- `layouts/partials/sessionize-data.html` normalises it (sessions with Europe/Dublin RFC 3339 times, room, speaker ids; speakers with tagline, bio, photo, links). Use with `partialCached`
- There is no `data/speakers.yml` / `data/sessions.yml` / `data/schedule.yml` any more: edit the programme in Sessionize and redeploy

**Ticket prices: Tito** (see `layouts/partials/tito-data.html`)

**`data/sponsors.yml`**
- Sponsor tiers: Platinum, Gold, Silver, Community
- Each sponsor: name, logo, website, tier

**`data/team.yml`**
- Organising team members

**`data/site.yml`**
- About section content (feature cards)

**Financial aid page (feature flag)**
- `params.financialAidEnabled` (default `false`): when off, `/financial-aid/` is not built and its footer/tickets links are hidden
- The page is added by a content adapter, `content/_content.gotmpl` (front matter cannot read site params); its body lives in `assets/content/financial-aid.md`, not in `content/`
- `params.financialAidOpens` / `financialAidCloses` (`YYYY-MM-DD`, closing day inclusive) and `financialAidUrl` drive the `financial-aid-status` shortcode (badge and "How to Apply" text: to be announced, opening soon, open, closed). Computed at build time: redeploy on the opening and closing days
- Policy: cap of €350 per person, requests well above it are declined; priority to people living in Ireland, then the UK, then Europe

**`data/dublin.yml`**
- "Discover Dublin" section: intro text, gallery images, highlights (attractions), transport options
- Structure: `intro`, `gallery[]`, `highlights[]`, `transport[]`
- Accessed: `hugo.Data.dublin`

**Why data files?** Allows non-technical team members to update content without touching templates. Enables programmatic manipulation and structured data generation.

### SEO Structured Data System

The site implements **comprehensive JSON-LD schemas** across three layers:

**Layer 1: Homepage (`layouts/partials/structured-data.html`)**
- While `editionStatus = "planning"`, the ConferenceEvent and Event schemas are not emitted (no confirmed date or venue); Organization, WebSite and BreadcrumbList stay
- Event schema: Full conference details (dates, location, pricing, organizer)
- Organization schema: Python Ireland with contact info
- WebSite schema: Site metadata
- BreadcrumbList schema: Navigation hierarchy for interior pages

**Layer 2: Speakers (`layouts/partials/structured-data-speakers.html`)**, built from Sessionize
- ItemList of Person nodes (name, tagline as `jobTitle`, bio, photo, `sameAs` links)
- `performerIn` links each speaker to their sessions

**Layer 3: Schedule (`layouts/partials/structured-data-schedule.html`)**, built from Sessionize, on `/schedule/` and `/grid/`
- One EducationEvent (schema.org has no "EducationalEvent") per accepted session in an `@graph`: exact `startDate`/`endDate`, room as `location` (venue `address`, `containedInPlace` the venue), `performer` references, `superEvent` → main event
- The homepage Event also lists all speakers as `performer`

**Key Pattern:** Use `@id` for cross-references: speakers are `{{ site.BaseURL }}speakers/#<sessionize speaker id>`, sessions `{{ site.BaseURL }}schedule/#session-<sessionize session id>`. Build JSON-LD objects with `dict` + `jsonify | safeJS` rather than string templating, so titles and bios are escaped correctly.

**Time zone:** Dublin is on GMT (`+00:00`) in November, IST (`+01:00`) in summer. `eventStartDate`/`eventEndDate` in `hugo.toml` must carry the right offset.

**Documentation:** See `docs/STRUCTURED-DATA.md` for complete schema details and validation instructions.

## Content Security Policy (CSP)

HTTP security headers are defined in `static/_headers` (served by Netlify on every response).

### Adding a third-party service

When adding any external script, stylesheet, or font, you **must** update the `Content-Security-Policy` header in `static/_headers`. The CI check (`scripts/check-csp.py`) will fail if a domain referenced in templates is missing from the CSP.

**Steps:**

1. Add the domain to the appropriate directive(s) in `static/_headers`:

   | Resource type | Directive |
   |---|---|
   | `<script src="...">` | `script-src` |
   | `<link rel="stylesheet">` or `<link rel="preload" as="style">` | `style-src` |
   | Font files | `font-src` |
   | `<link rel="preconnect">` | `connect-src` |
   | `<img src="...">` | `img-src` (note: `https:` is a wildcard for all HTTPS images) |

2. If the service **dynamically loads additional sub-resources** at runtime (e.g. a JS file that then injects a CSS or loads fonts), declare it in `csp-dynamic-loaders.yml`:

   ```yaml
   - name: My Service
     trigger:
       directive: script-src
       domain: cdn.myservice.com
     also-loads:
       - directive: style-src
         domain: cdn.myservice.com   # CSS injected by the JS
       - directive: font-src
         domain: fonts.myservice.com
   ```

3. Run the checker locally to verify before pushing:

   ```bash
   python scripts/check-csp.py --verbose
   ```

### CI enforcement

`.github/workflows/csp-check.yml` runs `scripts/check-csp.py` on every PR that touches `layouts/`, `static/_headers`, or `csp-dynamic-loaders.yml`. A missing domain causes the check to fail with a precise error message pointing to the file and line.

### Background

The Bree brand font (Adobe Fonts / Typekit) stopped loading in production because `use.typekit.net` was present in `script-src` and `font-src` but missing from `style-src`. Typekit's JS dynamically injects a stylesheet — invisible to static analysis — which the browser blocked. This checker was introduced to prevent that class of regression.
